# LAIM: динамика ключевой метрики

Тест сравнивает итоговые оценки мониторинга с официальным baseline подтверждённого определения v3. Он не выбирает формулу и не пересобирает `main_metric` из голосов/колонок корзины.

## Границы доверия

Принимаются только `scored_df` с назначением monitoring, совпадающими `definition_id` и `assessment_run_id`, а также `assessment_result` v2 с назначением monitoring, тем же определением/прогоном и допуском судьи green/amber.

Ручной `perv_validation_km` и второй контракт `metric_spec` удалены. `baseline.reconciliation=mismatch` запрещает допуск. Калибровочный holdout, чужая корзина, иной прогон или оценки вне `evaluation.score_values` не дают результата КМ. Обратное направление шкалы явно не поддерживается, вместо неверного «снижения» возвращается недоступность.

## Что измеряет текущий тест

Единица и веса берутся из определения; dialogue учитывается один раз. Отказы судьи учитываются отдельно; число пригодных единиц и допустимая доля отказов ограничены настройками. Цвет определяется относительно baseline и порогов green/red с учётом текущего интервала.

**Статистический production-допуск ещё не завершён.** Реализация интервала пока сохраняет Wilson/Kish и нормальную аппроксимацию, а поправка на смещение использует калибровку reference. Они не доказывают корректность вывода при зависимых turns, кластерной выборке, неслучайных отказах и переносе смещения на иной поток. Это открытый блок исследования, а не гарантированно корректный универсальный тест. Перенос v3 закрывает происхождение и смысл входов, но не закрывает этот блок.

Пороги и формат отчёта остаются в descriptor; выход `all_results` совместим с агрегатором, сводный статус при недоступности — gray/not_computable.

```bash
python3 -m pytest -q
ruff check .
```

В `all_results` сохраняются `definition_id` и `run_id` оценивания; агрегатор сверяет их с текущим `assessment_result`.
