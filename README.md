# LAIM: динамика ключевой метрики

Нода проверяет принадлежность итоговых оценок судьи и показывает статистику полученного набора по определению v3. КМ всего отчётного периода по одной reference-калибровке не вычисляется: подтверждён контрпример ложного green при реальном падении качества .92 → .64.

## Границы доверия

Принимаются только `scored_df` с назначением monitoring, совпадающими `definition_id` и `assessment_run_id`, а также `assessment_result` v2 с назначением monitoring, тем же определением/прогоном и допуском судьи green/amber.

Ручной `perv_validation_km` и второй контракт `metric_spec` удалены. `baseline.reconciliation=mismatch` запрещает допуск. Калибровочный holdout, чужая корзина, иной прогон или оценки вне `evaluation.score_values` не дают результата КМ. Обратное направление шкалы явно не поддерживается, вместо неверного «снижения» возвращается недоступность.

## Что измеряет текущий тест

Единица и веса берутся из определения; dialogue учитывается один раз. После гейтов принадлежности, допуска и достаточности нода возвращает `not_computable / gray / period_estimate_unidentified`. Это относится ко всем текущим proxy-входам — с reference bias, с нулевым bias и без него. Наличие 10 000 оценок и green-допуска не подтверждает перенос ошибки судьи.

`km_monitoring`, `km_delta`, `interval`, `judge_bias` равны null. Сохраняются baseline и наблюдаемые оценки судьи в `provenance`; они не выдаются за человеческое качество периода. Невалидные и неполные входы сохраняют свои более конкретные reason codes.

Удалены применение reference bias и выдача Wilson/Kish за интервал КМ периода. Контур пока не принимает независимый manifest полного периода и его человеческую контрольную разметку; поэтому положительный вывод не разрешается самодекларацией в `assessment_result`. Следующая реализация требует привязки к периоду, корректного дизайна отбора и проверенного метода прямой/комбинированной оценки. [Экспертное ревью и контрпример](https://github.com/vilkafork21/laim/issues/9).

Пороги и формат отчёта остаются в descriptor; выход `all_results` совместим с агрегатором, сводный статус при недоступности — gray/not_computable.

```bash
python3 -m pytest -q
ruff check .
```

В `all_results` сохраняются `definition_id` и `run_id` оценивания; агрегатор сверяет их с текущим `assessment_result`.

## Неизвестные оценки: S1a

Если хотя бы одна полученная единица не оценена, нода возвращает
`not_computable / gray / judge_refusals`, а `km_monitoring`, `km_delta`, `interval`
равны null. Среднее успешных оценок не публикуется как КМ полного периода.
Настройка `max_invalid_share` удалена: доля отказов ниже произвольного порога
не доказывает случайность их возникновения. Технический порог отказов внутри
ассесора остаётся его отдельным правилом; он не разрешает популяционный вывод KM.

В `provenance` сохраняются:

- `observed_mean` — среднее известных score, без поправки judge bias;
- `weight_sum` — масса оценённых, `total_weight` — масса всех полученных единиц;
- `refused_weight`, `refused_weight_share` — масса неизвестных и её доля;
- `completion_bounds: {lower, upper, scope: "received_units"}` — границы среднего
  при всех допустимых заполнениях неизвестных score.

Для S = Σ известных w·score, W = Σ всех w, M = Σ весов отказов и утверждённой
шкалы [L,U] границы равны [(S+M·L)/W, (S+M·U)/W]. Они вычисляются в O(n),
не требуют случайности отказов и не заполняют исходные строки выдуманными оценками.
В summary при отсутствии известных оценок среднее null и границы [L,U];
для пустого набора границы null. Если upstream отказал до гейтов принадлежности
и допуска, KM возвращает его причину без расчёта этих границ. Сессионная единица и её вес учитываются один раз.

Это **не доверительный интервал**, не границы ошибки судьи и не оценка
неотобранных обращений периода. Они относятся к полученному набору при фиксированных
известных score. Поэтому даже узкие границы сами по себе не дают computed KM
периода. Отчёт показывает их отдельно и не рисует точечный график неизвестной КМ.

Контрольный пример: 720 успехов, 80 дефектов и 200 отказов при baseline=1.
Прежний код давал 0.9/green; новый показывает observed_mean=0.9,
completion_bounds=[0.72,0.92] и отсутствие вывода. Если независимо раскрыть все
200 неизвестных как score=0, наблюдаемое среднее полученного набора станет .72.
Без подтверждения ошибки судьи и принадлежности всей совокупности это по-прежнему
не даёт светофор качества периода.

Следующий шаг — вывод для конечного отчётного периода с учётом отбора сессий,
доли охвата, ошибки судьи и неизвестных оценок. Арифметические границы не заменяют
эту статистическую задачу. [Исследование S1](https://github.com/vilkafork21/laim/issues/3).
